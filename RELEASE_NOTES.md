# Bitora Commander 2.9.4 — надёжность и нагрузочные испытания

- Журнал восстановления локальных копирований теперь принудительно записывается на диск (`fsync`) перед атомарной заменой файла. Это повышает устойчивость при сбоях, но не гарантирует сохранность при любых отказах оборудования.
- Для контрольных точек сетевых передач (`partial-store.js`) добавлена принудительная запись на диск до фиксации JSON-файла.
- В Windows CI добавлен нагрузочный тест копирования дерева из 2 001 файла с SHA-256-проверкой большого файла и выборочной проверкой остальных.
- Добавлен тест сохранения сетевых контрольных точек при повторном создании хранилища после завершения процесса.
- Дополнительные архивные проверки: ZIP с AES-256, неверный пароль, пропавший том многотомного архива и отсутствие частично опубликованных данных.
- Сохраняются тесты аварийного завершения дочернего процесса и восстановления проверенного префикса.

## Известные ограничения

Реальное отключение питания и физический сбой носителя не воспроизводятся GitHub Actions. Для 3.0 остаются ручные испытания на Windows 10/11 и завершающая проверка интерфейса; успешный CI не равнозначен гарантии отсутствия потери данных при любом аппаратном отказе.
